# Ubuntu Chiseled integration fixtures

This directory is isolated scaffolding for the two Ubuntu Chiseled filesystem
layouts. It does not modify or depend on the existing single-arch integration
suite. The package tests and synthetic fixtures remain network-independent;
registry inspection is opt-in, while executable patch validation lives in the
dedicated `test/e2e/chisel` suite.

## Contents

- `real-images.json`: immutable image-index and child-manifest digests plus the
  filesystem metadata observed on each inspected platform.
- `manifest-schema-1.0/`: a small deterministic zstd-compressed JSONWall schema
  1.0 manifest. `expected.json` records its known package, slice, content, path,
  and owned-path counts.
- `full-status-no-tools/`: a locally buildable fixture for the Microsoft .NET
  layout. It retains `/var/lib/dpkg/status`, removes the `Status:` fields to
  match the real image, and removes all required target-side dpkg tools.
- `native-manifest-local/`: a native manifest-only root generated by Chisel.
  It pins the Ubuntu 24.04 release definitions to commit
  `ca7ad8113998470ff77231af799c363c4a48feca`.

### Observed apt-less full-status layout

All three Microsoft platforms have:

- `/var/lib/dpkg/status`
- no `/var/lib/dpkg/status.d`
- no `/var/lib/chisel/manifest.wall`
- none of `apt-get`, `apt-mark`, `dpkg`, `sh`, `grep`, or `tee`
- seven package control paragraphs
- zero `Status:` fields

The absence of `Status:` is intentional and is represented in both
`real-images.json` and the synthetic Dockerfile. The control paragraphs still
contain package names, versions, architectures, dependencies, and descriptions.

## Tests

The default package test validates only checked-in data and the compressed
synthetic manifest:

```bash
go test ./integration/chisel -count=1 -v
```

Registry inspection is explicitly opt-in. It requires `crane` and registry
network access. If either the opt-in or tool is absent, the test skips safely:

```bash
COPA_CHISEL_INSPECT_REAL_IMAGES=1 \
  go test ./integration/chisel -run TestInspectPinnedRealImages -count=1 -v
```

The opt-in test verifies index and child digests, image config, layout paths,
missing tools, dpkg status hashes/counts, zstd manifest hashes, and JSONWall
record counts. It uses `crane export`; it never starts a container or invokes a
binary from either target image.

The shell-only synthetic manifest check remains available for environments
with `jq` and `zstd`:

```bash
integration/chisel/fixtures/manifest-schema-1.0/verify.sh
```

Executable patch validation uses digest-pinned Canonical, Microsoft, and
community images from `test/e2e/chisel/fixtures/test-images.json`:

```bash
make build

docker pull --platform linux/amd64 \
  ghcr.io/project-copacetic/copacetic/chisel@sha256:587015954e14bf51aea440e69c8bf30bd010abd57ed8dd42c19e2159577e8c80

COPA_BIN="$(pwd)/dist/$(go env GOOS)_$(go env GOARCH)/release/copa"
go test ./test/e2e/chisel \
  --addr=docker:// \
  --copa="$COPA_BIN" \
  -timeout 55m \
  -v
```

See `test/e2e/chisel/README.md` for the test matrix, prerequisites, and focused
`-run` commands.

## Manual registry inspection commands

```bash
FULL_STATUS='mcr.microsoft.com/dotnet/runtime:8.0.0-jammy-chiseled@sha256:f8d3477e689e1d95548f0180caeb7349c233dbf421aa0ba6ced8ab16d3c6e073'
NATIVE='docker.io/ubuntu/dotnet-runtime:8.0-24.04_stable_145@sha256:b82dacfba50e41a83f2b1ab7848cff634a112a07437a0bf50a990ef086dd98b1'

docker buildx imagetools inspect "$FULL_STATUS"
docker buildx imagetools inspect "$NATIVE"
crane digest "$FULL_STATUS"
crane digest --platform linux/amd64 "$FULL_STATUS"
crane digest "$NATIVE"
crane digest --platform linux/amd64 "$NATIVE"
```

Inspect the apt-less full-status root without executing it:

```bash
crane export --platform linux/amd64 "$FULL_STATUS" /tmp/copa-full-status.tar
tar -tf /tmp/copa-full-status.tar | grep -E \
  '^(var/lib/(dpkg/status|dpkg/status.d|chisel/manifest.wall)|usr/bin/(apt-get|apt-mark|dpkg|grep|tee)|bin/sh)$'
tar -xOf /tmp/copa-full-status.tar var/lib/dpkg/status > /tmp/copa-dpkg-status
sha256sum /tmp/copa-dpkg-status
grep -c '^Package:' /tmp/copa-dpkg-status
grep -c '^Status:' /tmp/copa-dpkg-status || true
```

Inspect the native manifest root without executing it:

```bash
crane export --platform linux/amd64 "$NATIVE" /tmp/copa-native.tar
tar -tf /tmp/copa-native.tar | grep -E \
  '^(var/lib/(dpkg/status|dpkg/status.d|chisel/manifest.wall)|usr/bin/(apt-get|apt-mark|dpkg|grep|tee)|bin/sh)$'
tar -xOf /tmp/copa-native.tar var/lib/chisel/manifest.wall > /tmp/manifest.wall
sha256sum /tmp/manifest.wall
zstd --decompress --stdout /tmp/manifest.wall > /tmp/manifest.jsonwall
head -n 1 /tmp/manifest.jsonwall
jq -s '{
  records: length,
  packages: ([.[] | select(.kind == "package")] | length),
  slices: ([.[] | select(.kind == "slice")] | length),
  contents: ([.[] | select(.kind == "content")] | length),
  paths: ([.[] | select(.kind == "path")] | length)
}' /tmp/manifest.jsonwall
```

## Build the local synthetic fixtures

The full-status Dockerfile defaults to an immutable Ubuntu 24.04 image index
and does not access apt repositories:

```bash
docker buildx build \
  --platform linux/amd64 \
  --load \
  --tag copa-chisel-full-status:local \
  integration/chisel/fixtures/full-status-no-tools
```

The native fixture requires a Chisel v1.4.2 tooling image that contains Git,
CA certificates, and zstd. With the project tooling image built locally:

```bash
VALIDATOR_SOURCE_SHA256="$(shasum -a 256 cmd/chisel-validator/main.go | awk '{print $1}')"

docker buildx build \
  --platform linux/amd64 \
  --load \
  --build-arg "COPA_VALIDATOR_SOURCE_SHA256=${VALIDATOR_SOURCE_SHA256}" \
  --tag copa-chisel:local \
  --file images/chisel/Dockerfile \
  .

docker buildx build \
  --platform linux/amd64 \
  --load \
  --build-arg CHISEL_TOOL_IMAGE=copa-chisel:local \
  --tag copa-native-chisel:local \
  integration/chisel/fixtures/native-manifest-local
```

The native fixture fetches only the pinned public Chisel release commit. It
uses no Ubuntu Pro, ESM, FIPS, private-archive, or package-manager credentials.

## Executable real-image patch validation

The previous blocker to executable native patch smoke tests has been removed.
The `test/e2e/chisel` suite now validates:

- comprehensive native re-cuts for Canonical and community images;
- report-driven and comprehensive updates for Microsoft's apt-less full-status
  layout;
- runtime and image-configuration preservation;
- absence of apt, dpkg, BusyBox, and shell tooling in patched outputs;
- no package downgrades and complete native manifest package metadata;
- no-update repatching; and
- partial-platform OCI output with untouched platform descriptors and blobs.

CI pulls the published tooling image by immutable manifest-list digest (`ghcr.io/project-copacetic/copacetic/chisel@sha256:587015954e14bf51aea440e69c8bf30bd010abd57ed8dd42c19e2159577e8c80`). The publication workflow verifies all supported platforms, SBOM and provenance attestations, Chisel commit labels, the validator source checksum, and amd64/arm64 runtime behavior before assigning the versioned tag.

Trivy remains applicable to the full-status layout only. Native
`manifest.wall` coverage is comprehensive-update-only until a scanner can
inventory that metadata format.
